# План реализации: Экспорт и Импорт проектов в формате `.biui`

## 1. Концепция и Архитектура формата
Формат `.biui` будет представлять собой единый файл, содержащий полное состояние приложения (Снапшот проекта). 
В соответствии с текущими ограничениями (запрет на установку библиотек без разрешения), базовая реализация будет использовать стандартный JSON, сохраняемый с кастомным расширением `.biui`.

**Структура данных (BiuiProjectState):**
```typescript
interface BiuiProjectState {
  version: string; // Версия формата (для совместимости будущих обновлений)
  nodesState: {
    nodes: any[]; // Состояние всех узлов (DataSource, Transform, Visualization)
    edges: any[]; // Связи между узлами
  };
  dataState: {
    tables: Record<string, any[]>; // Распарсенные данные таблиц
    metadata: Record<string, any>; // Метаданные столбцов (типы данных, уникальные значения)
  };
  dashboardState: {
    layout: any[]; // Расположение виджетов
    config: Record<string, any>; // Настройки дашборда
  };
  generationState: {
    configs: Record<string, any>; // Сгенерированные LLM конфигурации (например, ECharts)
  };
}
```

## 2. Пошаговый план разработки

### Шаг 1: Разработка слоя сериализации (Экспорт)
- [ ] Создать утилиту `ProjectExportService`.
- [ ] Написать функции агрегации состояния из текущих сторов (Zustand/Redux/Context).
- [ ] Сформировать единый объект `BiuiProjectState`.
- [ ] Реализовать функцию скачивания файла: преобразование объекта в строку `JSON.stringify`, создание `Blob` (type: `application/json`), и генерация ссылки для скачивания файла `project.biui`.

### Шаг 2: Разработка слоя десериализации (Импорт)
- [ ] Создать утилиту `ProjectImportService`.
- [ ] Реализовать чтение локального файла через браузерный API `FileReader`.
- [ ] Добавить базовую валидацию схемы (проверка наличия `version`, `nodesState`, `dataState`).
- [ ] Написать функции гидратации (hydration) для каждого стора приложения (очистка текущего состояния и загрузка нового).

### Шаг 3: Интеграция в пользовательский интерфейс (UI)
- [ ] Добавить кнопки «Экспорт проекта (.biui)» и «Импорт проекта» в главное меню или хедер.
- [ ] Настроить скрытый `<input type="file" accept=".biui" />` для обработки загрузки.
- [ ] Реализовать обработку ошибок: вывод уведомлений пользователю в случае битого файла или несовпадения версий.

## 3. Вопросы, требующие решения оператора

Перед началом написания кода, необходимо определиться со следующими моментами:

1. **Размер файлов и сжатие:** Если наборы данных (таблицы) очень большие, обычный JSON может весить десятки мегабайт. Разрешена ли установка библиотеки (например, `fflate` или `jszip`) для сжатия JSON в ZIP-архив под капотом? Если нет — используем чистый JSON.
2. **Исходные файлы:** Нужно ли сохранять в проекте сами исходные файлы (например, загруженные CSV/Excel), или достаточно сохранить уже распарсенные данные, которые лежат в памяти приложения?
3. **Хранилище состояния:** Какие именно инструменты сейчас используются для хранения состояния (Zustand, React Context, Redux)? Это необходимо для правильной реализации механизма гидратации (загрузки данных обратно в приложение).
