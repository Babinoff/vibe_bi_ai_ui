# План реализации: Экспорт и Импорт проектов в формате `.biui`

## 1. Концепция и Архитектура формата
Формат `.biui` будет представлять собой ZIP-архив (содержащий JSON-файл с состоянием приложения), с кастомным расширением `.biui`. Это позволит значительно уменьшить размер файлов при сохранении больших объемов исходных данных.

**Используемая библиотека для сжатия:** 
- `fflate` (версия `0.8.2`) — сверхбыстрая, легковесная (без зависимостей) библиотека для работы с ZIP в браузере. Альтернативой может быть `jszip` (версия `3.10.1`), но `fflate` предпочтительнее для современных React-приложений из-за малого размера бандла. Жду проверки `fflate@0.8.2` на предмет уязвимостей.

**Структура данных (BiuiProjectState):**
На основе архитектуры проекта (используется стейт-менеджер **Zustand** в `src/store/useStore.ts`), мы будем экспортировать и импортировать нужные срезы этого стора. 

```typescript
interface BiuiProjectState {
  version: string; // Версия формата
  store: {
    nodes: any[]; // Состояние узлов (без промежуточных вычисленных данных)
    edges: any[]; // Связи между узлами
    dataSources: any[]; // ИСХОДНЫЕ данные (сырые CSV, сохраненные пользователем)
    widgets: any[]; // Настроенные виджеты дашборда
    // Настройки приложения (тема, провайдеры)
  };
}
```
*Примечание: Сохраняются только исходные данные. Все промежуточные вычисления (результаты парсинга, результаты Python-трансформаций) будут очищаться при экспорте для экономии места и генерироваться заново при запуске.*

## 2. Пошаговый план разработки

### Шаг 1: Интеграция библиотеки сжатия
- [ ] Ожидание проверки оператором библиотеки `fflate@0.8.2`.
- [ ] Установка библиотеки (строго после получения разрешения).

### Шаг 2: Разработка слоя сериализации (Экспорт)
- [ ] Создать сервис `ProjectExportService`.
- [ ] Собрать необходимые данные из Zustand (`useStore.getState()`), очистив ноды от промежуточных данных (оставить только код и настройки).
- [ ] Сформировать JSON, запаковать его в ZIP с помощью `fflate`.
- [ ] Реализовать сохранение файла `.biui` (генерация Blob с типом `application/zip` и скачивание).

### Шаг 3: Разработка слоя десериализации (Импорт)
- [ ] Создать сервис `ProjectImportService`.
- [ ] Реализовать чтение `.biui` файла через `FileReader`.
- [ ] Распаковать ZIP-архив с помощью `fflate` и распарсить JSON.
- [ ] Написать функцию гидратации для Zustand-стора (очистка текущего состояния, загрузка нового состояния).

### Шаг 4: Глобальная кнопка "Play" (Последовательный запуск графа)
- [ ] Добавить кнопку "Play" (Запустить всё) в верхнее меню (в `NodeEditor`).
- [ ] Реализовать логику **последовательного** выполнения графа:
  - Найти стартовые ноды (источники данных) и запустить их парсинг.
  - Использовать топологическую сортировку (или обход в ширину по связям `edges`), чтобы запускать выполнение узлов строго по цепочке.
  - Запускать скрипты (Pyodide, LLM-генерации) последовательно, дожидаясь завершения предыдущей ноды, чтобы избежать зависания браузера.
  - Добавить визуальную индикацию выполнения для каждой ноды.

### Шаг 5: Интеграция UI экспорта/импорта
- [ ] Добавить кнопки «Экспорт проекта» и «Импорт проекта» в верхнюю панель управления.
- [ ] Настроить скрытый `<input type="file" accept=".biui" />` для загрузки проектов.
- [ ] Добавить обработку ошибок (уведомления о поврежденном архиве или несовпадении версий).
